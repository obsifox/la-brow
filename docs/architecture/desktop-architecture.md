# Desktop Architecture

## Targets

| Target | Status |
| --- | --- |
| Linux x86_64 | scaffolded, not built |
| Windows x86_64 | scaffolded, not built |
| macOS universal | scaffolded, not built |

Target status is recorded in `config/build/targets.yaml`. A target may not be described as supported before a build and its tests pass on that target.

## Packaging Plan

| Concern | Plan |
| --- | --- |
| Installer | Platform installer produced by the platform packaging toolchain |
| Uninstaller | Provided by the same toolchain and verified by an uninstall test |
| Portable build | Archive build with a relocation tolerant data directory |
| File associations | Registered per platform, removable at uninstall |
| Default browser integration | Offered to the user, never applied silently |
| Protocol handling | Registered for the documented schemes only |
| Crash recovery | Session snapshot restore, matching the shell model in `browser/shell.py` |
| Update mechanism | Signed artifacts only, verification before installation |
| Configuration migration | Profile migrations run before activation, as in `profiles/migrations.py` |

## Update Security Requirements

1. Update metadata is fetched over a verified transport
2. Artifact signatures are verified against a pinned public key
3. Installation proceeds only after verification succeeds
4. Rollback is available when installation or the first run fails
5. An unsigned artifact is never installed

## Preference Application

The desktop shell consumes the artifacts generated by `gecko/integration.py`:

- Preferences rendered into the profile preference file
- Enterprise policy document for resolver selection
- Environment document delivered through a privileged internal channel for diagnostics

## Status Statement

Desktop packaging is documented and structured, not executed. The measured environment cannot host the engine build, so no desktop artifact exists and no support claim is made.
